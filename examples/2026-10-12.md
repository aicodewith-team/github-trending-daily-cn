# GitHub Trending 中文日报 · 2026-10-12

## 今日看点

今天的主线很明确：AI 不只负责生成内容，也开始接管逆向分析、制图和创作工作流。另一边，AnyPS5、AirLLM 和 Apollo 11 源码又把注意力拉回底层工程：真正困难的往往不是做出演示，而是处理兼容性、资源约束和可验证的细节。

## 榜单

### 1. morluto/rea（TypeScript，今日 +25,599 star，MIT，创建于 2026-04-14）

- **到底干嘛的**：给 AI Agent 配一套逆向工程工具，让它分析原生二进制、JavaScript/Electron 应用、.NET 程序和网站。即使没有源码，也能调查某项功能如何实现，并给出证据和结论的局限。
- **有意思的点**：通过一个 MCP 接入多类分析工具；原生分析可复用 Hopper、Ghidra 或 IDA，静态 JavaScript 分析则不需要原生分析引擎。分析在本地运行。
- **能用来干嘛**：看到某款应用里一个值得借鉴的交互功能，让 Agent 分析其行为和二进制实现，再为自己的项目做一个版本。
- **要注意**：仓库创建仅约半年；原生分析仍依赖 Hopper、Ghidra 或 IDA 等工具，README 也明确强调结论会附带局限。
- [GitHub](https://github.com/morluto/rea)

### 2. boykopovar/AnyPS5（C++，今日 +3,952 star，GPL-2.0，创建于 2026-08-03）

- **到底干嘛的**：把 PS5 可执行文件转换成 Linux 或 Windows 的原生格式，并补上可动态链接的系统 PRX 库实现。它走的是重链接路线，不是模拟器，也不需要单独的运行时进程。
- **有意思的点**：着色器重编译器可以生成 SPIR-V，并可在启用 `ANYPS5_ENABLE_SPIRV_TOOLS` 时通过 Spirv-Tools 验证；输入层支持 SDL 映射手柄，也能用 `anyps5-input.ini` 配置键鼠。
- **能用来干嘛**：研究合法取得的 PS5 程序如何移植到 PC，并对照兼容性列表验证运行效果。
- **要注意**：项目创建才两个多月，兼容范围显然仍有限；README 只举出 Dreaming Sarah 在 GTX 1050 Ti 与 i5-7500 上稳定 60 fps。未支持或异常状态会直接抛出 `std::runtime_error` 并终止进程；使用者还需自行确保二进制来源和使用方式合法。GPL-2.0 only 也会约束衍生分发。
- [GitHub](https://github.com/boykopovar/AnyPS5)

### 3. storytold/artcraft（Rust，今日 +2,957 star，Apache-2.0，创建于 2022-03-31）

- **到底干嘛的**：面向艺术家、设计师和影视创作者的 AI 图像与视频制作 IDE。它把提示词生成变成可视化工作流，允许先搭场景、定构图，再选择模型生成。
- **有意思的点**：同时提供 2D 图层合成、背景移除、绘图、3D 图像合成、图像转 3D 网格、角色摆姿和相机定位，还能用 3D 素材套件做 scene blocking。
- **能用来干嘛**：先搭建一个房间并放置虚拟角色，再规划多个镜头，以保持同一场景的位置和构图一致。
- **要注意**：所给 README 片段未提及支持哪些具体生成模型、运行硬件要求或各项功能的完成度。
- [GitHub](https://github.com/storytold/artcraft)

### 4. cathrynlavery/diagram-design（HTML，今日 +1,083 star，MIT，创建于 2026-04-16）

- **到底干嘛的**：一个让编码 Agent 绘制编辑风格图表的 Skill，支持 44 类图表。结果是单个自包含的 HTML + SVG 文件，双击即可打开。
- **有意思的点**：能从自然语言选择图表类型，也能读取网站的配色与字体来匹配品牌；README 还明确支持从 draw.io、Mermaid 或 Excalidraw 导入，并导出 PNG 或 SVG。
- **能用来干嘛**：让 Agent 画一张包含前端、后端、数据库和 Redis 的系统架构图，直接交付为可浏览的 `.html` 文件。
- **要注意**：官方构建只从该仓库发布；第三方 Agent Skill 主机的具体兼容和更新方式各不相同。README 指向 `PRIVACY.md` 说明联网发送的数据，安装前值得先看。
- [GitHub](https://github.com/cathrynlavery/diagram-design)

### 5. bilawalsidhu/gods-eye-view（JavaScript，今日 +886 star，未声明，创建于 2026-06-22）

- **到底干嘛的**：在浏览器里用写实 3D 地球聚合公开空间情报，包括飞机、船舶、卫星、地震、交通和公共摄像头，并支持实时 AI 语音控制。
- **有意思的点**：把飞行器应答机、船舶信标、轨道要素、地震仪和公共摄像头数据放到同一个可探索界面；可以从全球视角一路查看单架飞机、单艘船或具体街道。
- **能用来干嘛**：在一张地球界面上同时观察某一区域附近的航班、船舶、地震与公共摄像头信号。
- **要注意**：交通流是基于真实道路与聚合位置数据的模拟结果，CCTV 机位和火箭发射轨迹只是粗略估计；部分数据虽为实时或定期刷新，但不能把整张图当成精确监控系统。仓库未声明明确的开源协议。
- [GitHub](https://github.com/bilawalsidhu/gods-eye-view)

### 6. pytorch/pytorch（Python，今日 +315 star，未声明，创建于 2016-08-13）

- **到底干嘛的**：提供类似 NumPy 的张量计算、GPU 加速和基于 tape 的自动微分，是构建动态神经网络的基础框架。
- **有意思的点**：核心组件包括 `torch`、`torch.autograd` 和 `torch.nn`；强调 Python-first，也能与 NumPy、SciPy、Cython 等现有 Python 工具配合扩展。
- **能用来干嘛**：在 GPU 上训练需要动态计算图的神经网络，同时用自动微分完成梯度计算。
- **要注意**：安装方式会随 NVIDIA CUDA、AMD ROCm、Intel GPU 或 Jetson 平台而变化，不能只看一条通用命令。给定数据将协议标为未声明，所给 README 片段中的许可证正文未展示。
- [GitHub](https://github.com/pytorch/pytorch)

### 7. lyogavin/airllm（Jupyter Notebook，今日 +548 star，Apache-2.0，创建于 2023-06-12）

- **到底干嘛的**：通过逐层流式加载模型权重，大幅压低大模型推理的显存占用；README 宣称无需量化、蒸馏或剪枝，即可在单张小显存显卡上运行超大模型。
- **有意思的点**：训练时逐层流式读取冻结权重，只把 adapter 留在 GPU；对 MoE 模型则只加载当前 token 实际路由到的专家。Qwen3.8-Flash-Next 的大体积 n-gram 表会映射到主机文件，解码层再流式载入。
- **能用来干嘛**：在显存有限但具备足够内存和磁盘的本地机器上，实验 Qwen3.8、DeepSeek-V3 或 Kimi K3 等大模型。
- **要注意**：省显存不等于省掉其他资源。README 给出的 Qwen3.8-Flash-Next 案例仍需约 360GB checkpoint 磁盘和 64GB 主机内存，还依赖特定 `transformers` 开发版本；Kimi K3 另需 `compressed-tensors` 与 `flash-attn`。所给片段没有展示 Quickstart 的实际命令。
- [GitHub](https://github.com/lyogavin/airllm)

### 8. chrislgarry/Apollo-11（Assembly，今日 +466 star，未声明，创建于 2014-04-03）

- **到底干嘛的**：保存阿波罗 11 号制导计算机的原始汇编源码，包括指令舱使用的 Comanche055 和登月舱使用的 Luminary099。
- **有意思的点**：代码由 Virtual AGC 与 MIT Museum 数字化；项目接受针对仓库转录内容与 Luminary 099、Comanche 055 原始扫描件之间差异的修正。
- **能用来干嘛**：对照原始扫描件研究阿波罗制导软件，或检查历史源码数字化过程中是否存在漏录和转录错误。
- **要注意**：它的目标是忠实保存历史源码，不是现代航天软件开发框架。仓库未声明明确的开源协议；所给 README 片段也未提供构建或运行命令。
- [GitHub](https://github.com/chrislgarry/Apollo-11)

## 编辑推荐

今天最值得直接上手的是 **cathrynlavery/diagram-design**。理由很实际：它的产物只是一个自包含的 HTML + SVG 文件，不需要先搭复杂服务；而且“让 Agent 画图”比“让 Agent 解释它画了什么”更容易当场验收。

README 给出的第一步是安装 Skill：

```bash
npx skills add cathrynlavery/diagram-design
```

安装后，可以直接让 Agent 制作一张包含 frontend、backend、database 和 Redis cache 的架构图。打开生成的 `.html`，基本就能判断它究竟是在认真做信息设计，还是只给 Mermaid 换了件衣服。
